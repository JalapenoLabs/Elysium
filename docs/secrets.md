# Secrets

Application secrets are stored in Postgres, encrypted. `.env` holds the key that encrypts them, alongside the
infrastructure credentials needed to start the stack. Application secrets never go in `.env`.

## The encryption key

`ELYSIUM_ENCRYPTION_KEY` is 32 random bytes, base64-encoded. Generate one with:

```sh
docker compose run --rm --no-deps api elysium-api generate-encryption-key
```

The API refuses to start if the key is missing or is not exactly 32 bytes. Compose also refuses to start the API
without it.

Losing the key makes every stored secret unrecoverable. Leaking it, together with a database dump, exposes them.
Back it up separately from database backups.

## Encryption

`api/src/crypto.rs` seals values with XChaCha20-Poly1305 and a fresh random 24-byte nonce per value. Each sealed
value is stored as one `BYTEA` envelope:

```text
version (1 byte) || nonce (24 bytes) || ciphertext || tag (16 bytes)
```

Every seal is bound to a context string that is authenticated but not stored. For LLM tokens the context is
`llms.secret_token:` followed by the row's UUID, and for satellite secrets `satellites.secret:` and the row's
UUID. A ciphertext copied into another row fails to open instead of
handing out the wrong credential. This is why LLM ids are generated by the API rather than by Postgres: the id
must exist before the token is sealed. The same holds for satellites.

The version byte identifies the envelope format and key generation. Today only version 1 exists.

## Handling in code

- Plaintext secrets travel as `secrecy::SecretString`, which prints as redacted and zeroizes on drop.
- Request tokens are validated while they are parsed, so a rejected token is never copied into an error report.
- No response ever includes a secret token, sealed or not. Tokens are write-only over HTTP.
- `Llm::secret_token` and `Satellite::secret` are the only ways to decrypt, for code that uses the credential.
  A satellite secret is decrypted only to connect, inside `api/src/fleet/`.

## Stored secrets

| Table        | Column                   | Context                  |
|--------------|--------------------------|--------------------------|
| `llms`       | `secret_token_encrypted` | `llms.secret_token:<id>` |
| `satellites` | `secret_encrypted`       | `satellites.secret:<id>` |

## Roadmap

- Key rotation: add a second key, open with either, seal with the new one, then re-seal rows in the background
  and bump the envelope version.
